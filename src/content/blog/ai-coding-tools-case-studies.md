Every big AI coding tool has a case study now. Anthropic has customers reporting 10x productivity. OpenAI has founders turning onboarding into an agent workflow. GitHub has PR cycle times cut by days. Google has an airline generating half its QA code automatically. Read them back to back and it sounds like the entire industry has been solved.

The number in the headline isn't the interesting part, though. The interesting part is *who measured it, how, and whether anyone outside the company selling the tool has checked*. We went through the public case studies behind the four biggest players — Claude Code, OpenAI's Codex, GitHub Copilot, and Google's Antigravity — and sorted the real evidence from the marketing copy.

## Claude Code (Anthropic): Strong Numbers, All Self-Reported

Anthropic's customer page is the most specific of the four. [Classmethod](https://claude.com/customers/classmethod), a Japanese cloud integrator, reports up to 10x productivity gains and says 99% of an open-source project it built ("rulesync") was implemented using Claude Code. [HubSpot](https://claude.com/customers/hubspot) says Claude Code accelerated a full frontend migration during its 2025 rebrand that would otherwise have taken months. Internally, Anthropic has published its own story of an engineer who let Claude Code run semi-autonomously against a class of production API errors — it shipped over 800 individual fixes and cut the error rate by a factor of 1,000.

Those are concrete, specific claims, not vague "productivity boost" language, and that's worth crediting. But every one of them is either Anthropic's own customer page or Anthropic's own engineering blog. There's no independent study in the mix, no third party auditing the "99%" or the "1,000x," and customer case studies are opt-in by design: companies with disappointing results don't submit testimonials.

**Grade: B+.** Best-documented specifics of the four, zero independent verification.

## Codex (OpenAI): Real Names, but the Headline Metric Is Usage, Not Outcome

OpenAI's September case study features three named companies — Basis, Clay, and Exa Labs — each turning a specific business process (new-hire onboarding, sales workflows, integrations) into a bounded Codex agent workflow rather than a general "use AI more" mandate. Virgin Atlantic's CFO separately credited Codex and ChatGPT Enterprise with productivity gains across several functions.

The number OpenAI leads with, though, is a usage stat: Codex now accounts for 64% of combined Codex-plus-ChatGPT tokens generated by enterprise customers. That's a real, measurable, and probably accurate number — but it tells you adoption is happening, not that the resulting code is good. High token share is consistent with a tool people love using and also consistent with a tool that requires a lot of back-and-forth to get right. The case study doesn't distinguish between the two.

**Grade: B-.** Specific named customers, but the flagship number measures engagement, not quality.

## GitHub Copilot (Microsoft): The Most Contested Evidence, Which Makes It the Most Honest

GitHub's own research, run with Accenture, reports real operational gains: average time to open a pull request dropped from 9.6 days to 2.4 days, PR volume rose 10.6%, and cycle time fell by 3.5 hours. Survey data layered on top shows high satisfaction — 88% say they complete tasks faster, 90% feel more fulfilled, 73% report staying in flow longer.

Here's what makes Copilot different from the other three: there's an independent, non-vendor-funded [longitudinal mixed-methods case study on arXiv](https://arxiv.org/abs/2509.20353) that looked at developer productivity with and without Copilot — and found no statistically significant change in commit-based activity after adoption. That's a direct contradiction of the satisfaction numbers, and it's a genuinely useful data point precisely because nobody at Microsoft signed off on it. Developers *feeling* more productive and developers *shipping* measurably more are turning out to be two different claims, and Copilot is the only one of the four tools where an outside study has actually tested the gap between them.

**Grade: A-.** Not because the results are the best, but because it's the only tool with real independent research to weigh against the vendor's own numbers.

## Antigravity (Google): Thinnest Evidence, and an Open Flag

Google's flagship number is AirAsia generating over 50% of its production QA code through Antigravity, published on Google's own blog. Outside that, independent comparisons of the tool describe the public case study base as thin: one industry review noted Antigravity "remains early in its enterprise maturity, with limited evidence of public deployment," still in public preview, no documented compliance certifications as of mid-2026, and a publicly reported RCE (remote code execution) issue. Gemini Code Assist, Google's other coding product, fares similarly — a single referenced case study (Dun & Bradstreet) with no specific metrics attached at all.

Some of this is simply a function of age: Antigravity shipped in November 2025 and hasn't had time to accumulate the case study library the other three have. But "too new to have evidence" and "has evidence" are different states, and right now Antigravity is in the first one.

**Grade: C.** Thinnest case study base, plus an unresolved security disclosure worth knowing about before betting production workflows on it.

## The Pattern Across All Four

Three things hold true regardless of which tool you're looking at, and they'll still be true for whatever tool replaces these four in a year or two.

**Vendor-published case studies are a ceiling, not an average.** Companies volunteer their best results. If a case study says "10x," that's the number from the customer who agreed to be quoted, not the median outcome across everyone using the product.

**Usage volume and code quality are different metrics, and case studies routinely blur them.** "% of code written by AI" and "tokens generated" tell you people are delegating work to the tool. They don't tell you whether that work needed rework, introduced bugs, or actually shipped.

**The presence of independent research is itself the strongest signal.** It's not that Copilot's academic study makes the tool look better — the finding was actually less flattering than the vendor survey. It's that the existence of outside scrutiny means someone had access to real usage data and no incentive to make the tool look good. That's worth more than another glowing testimonial.

## How to Read Any AI Coding Tool's Case Study

![Close-up of a hand marking a line on a printed research report with a highlighter, a laptop with a blurred code editor out of focus in the background](./images/ai-coding-tools-case-studies-checklist.webp)

A five-question checklist that holds up no matter which tools are on top when you're reading this:

1. **Who published it?** A customer page hosted on the vendor's own domain is marketing copy first. Treat every number on it as a best case.
2. **What's actually being measured?** Usage share, satisfaction surveys, and shipped-code quality are three different things. Know which one the headline number is.
3. **Is there a baseline?** "88% say they're faster" is a feeling. "PR open time went from 9.6 to 2.4 days" is a measurement. Only one of those can be wrong in a way you'd notice.
4. **Does an independent study exist for this tool at all?** Search for it specifically. Its existence matters more than its conclusion.
5. **What isn't mentioned?** No security disclosures, no compliance certifications, no failure cases — on a new or fast-growing product, that's usually a gap in the evidence, not proof there's nothing to report.

## FAQ

### Are AI coding tool case studies trustworthy?

They're trustworthy as evidence that *something* worked for *someone*, under conditions the vendor chose to publish. Treat the specific numbers as a best case, not an average, unless an independent source corroborates them.

### Which AI coding tool has the most independent research behind it?

GitHub Copilot, by a clear margin — it's the only one of the four with a published, non-vendor-funded longitudinal study, even though that study's findings complicate rather than confirm the marketing numbers.

### Does a high percentage of "AI-written code" mean the tool is better?

Not by itself. It measures how much work is being delegated to the tool, not whether that code shipped without rework or introduced more bugs. Pair it with a quality or defect metric before treating it as a win.

### Is Google Antigravity ready for enterprise production use?

It's earlier than the other three on public evidence: fewer documented deployments, no compliance certifications as of mid-2026, and a publicly reported RCE issue. That doesn't rule it out, but it means doing your own evaluation rather than leaning on its case study library.

### Should case studies alone decide which AI coding tool a team adopts?

No. They're a starting filter for which tools are worth a real trial, not a substitute for testing on your own codebase with your own definition of success.

## The Bottom Line

Line up the four biggest AI coding tools' case studies and the gap isn't really about which one has the biggest number — it's about which ones have any evidence beyond their own marketing page. Claude Code and Codex have specific, named customers and no outside verification. Antigravity has the thinnest record of the four and an open security flag. Copilot is the odd one out: the only tool with independent academic scrutiny, and that scrutiny didn't simply confirm the vendor's story. That's not a reason to default to Copilot — it's a reason to go looking for the same kind of scrutiny, or the lack of it, before trusting any tool's own case study about itself.
